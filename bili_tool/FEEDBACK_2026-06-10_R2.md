## 二、新功能需求

### 2.1 精校增加"辩证完整性"维度（加分项，非扣分项）

**背景**：用户评价视频8（福柯话语权力）时指出"过度强调矛盾的一方面，忽视矛盾的另一方面"，给"中等"评价。但辩证完整的视频很少，不应作为扣分项——应作为纯加分项，识别到才加分。

**方案**：在 `analyzer.py` 的 SYSTEM_PROMPT 中增加一条评估维度：

```
4. **辩证完整性**（加分项，可选标注）：
   视频是否满足以下任一条件：
   - 主动呈现与自身立场相反的观点/证据，并认真回应（非一笔带过）
   - 承认自身分析框架的局限或适用范围
   - 呈现了问题的多个面向，而非只推单一解释
   如果符合 → 在总结分析中标注 💡 亮点："辩证完整：呈现了反方观点并做出回应"
   如果不符合 → 不扣分，不标注（大多数视频都不符合，这是常态）
```

**理由**：DeepSeek 精校时已读全文，加一条判断零额外 API 成本。正则做不到（"另一方面"可能是修辞套路），只有 LLM 语义理解能做。

## 三、📝 评论扫描正则设计缺陷（本次发现的非代码问题）

尝试用正则扫描用户评论栏 `📝 我的评论` 时，以下写法会漏掉紧跟在 HTML 注释后的评论文字：

```python
# 错误：假设评论在 <!--...--> 的下一行
r'### 📝 我的评论\s*\n<!--.*?-->\s*\n(.+?)(?=\n\n###)'
```

实际笔记模板中，用户评论和 `-->` 可能在同一行：
```
### 📝 我的评论
<!-- 喜欢就写为什么喜欢，不喜欢写明原因 -->这个视频只能说中等吧……
```

### 推荐写法

```python
# 正确：不依赖注释与评论之间的换行
r'### 📝 我的评论\n(?:<!--.*?-->\s*)?(.+?)(?=\n###|\n---|\Z)'
```

`(?:<!--.*?-->\s*)?` 把注释+空白作为可选组，评论紧跟在后面也能捕获。注意 `.` 默认不跨行，用 `re.DOTALL`。

这个不涉及项目代码，是 AI 写 ad-hoc 扫描脚本时的注意事项。

### 3.2 💬 逐段看法扫描 — 同样的问题

`> 💬 你的看法：` 也存在相同的"空行误抓"陷阱。以下写法会在 💬 为空时误抓下一段落的标题和正文：

```python
# 错误：💬为空时仍匹配，抓到下一段内容
r'> 💬 你的看法：\s*\n\s*([^>\n].+?)(?=\n> 💬|\n【第|\n###)'
```

推荐写法：在捕获组前加非空断言，或者改用两步法——先用精确的 `💬 你的看法：\s*\n\s*(\S)` 判断是否有内容，有内容再解析。

```python
# 两步法
has_fb = re.search(r'> 💬 你的看法：\s*\n\s*(\S)', sec)
if has_fb:
    # 有实际内容，再解析
    ...
```

核心教训：Obsidian 笔记中的 `💬 你的看法：` 在无用户输入时，后面只有一个空白行然后跳到下一个标记。所有对此类字段的扫描都必须先判断非空再捕获。
