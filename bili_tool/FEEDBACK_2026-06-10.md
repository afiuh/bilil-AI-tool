# bili_tool 运维反馈 — 2026-06-10

## 一、Bug：精校输出被截断

**严重程度**：中（影响精校完整性，罕见但一旦出现破坏体验）

**位置**：`bili_tool/analyzer.py`

**现象**：视频1（"卡尔·荣格"42分钟，字幕11416字），总结分析的第三条"不足"被截断：
```
3. **夸大篇幅**：多次提及"1万2000字"，但实际文本远未达到，这种夸大可能降低可信
```
话没说完就断了。见笔记 `推荐-2026-06-10.md` 第171行。

**根因**：`analyze_subtitle()` 第63行 `max_tokens=8000`。精校分析输出 = 完整精校文本 + 每段批注 + 总结分析，万字级字幕的输出量容易超过 8000 tokens。DeepSeek 达到上限后直接截断（finish_reason="length"），代码未处理。

**修复方案**：
1. `max_tokens` 提升到 16384（DeepSeek 上限）
2. 检查 API 返回的 `finish_reason`，若为 `"length"` 打 warning 日志：`logger.warning(f"视频 {video_title} 精校输出可能被截断")`
3. （可选）长视频分两段调 API：一段出精校，一段出总结

**影响面**：所有字幕 >8000 字的视频都可能被截断。

## 二、新功能：L2 鸡汤指数检测

**背景**：当前精校推荐排第一的视频（评分 0.42）是典型"披着学术皮的鸡汤"——用荣格术语（投射、阴影、自性）包装情绪按摩，通篇 0 个具体出处引用，满篇比喻堆砌（皮球、信使、开关、钥匙、GPS、宝石、勋章……），但用户画像明确排斥"人生感悟/心灵鸡汤类"。

当前打分只看形式指标（时长、字数、分段、因果词），测不到内容质量，导致鸡汤类拿高分。

**需求**：在 `scoring.py` 的 L2 字幕采样阶段，新增 `score_chicken_soup()` 函数，计算"鸡汤指数"。

### 检测维度

#### 负向信号（命中的越多，越可能是鸡汤）

| 信号 | 计算方式 | 阈值参考 |
|------|---------|---------|
| 你字率 | `"你"出现次数 / 总字符数` | 视频1：约 0.025（每40字一个"你"） |
| 零出处引用 | 无《》、无具体人名（除核心人物外）、无年份数字 | 布尔值 |
| 比喻密度 | 比喻词数 / 段落数（匹配"就像/如同/是一把/是一座/仿佛/像……一样"） | 视频1：约 1.5 比喻/段 |
| 高情感词密度 | "痛苦/悲伤/温柔/拥抱/感动/温暖/灵魂/信念/勇气" | 辅助参考 |
| 结尾模板 | 匹配"愿你""你会发现""真正的……是""这就是" | 布尔值 |

#### 正向信号（命中的越少，越可能是鸡汤）

| 信号 | 计算方式 |
|------|---------|
| 出处密度 | 书名号《》数 + 具体年份（公元\d+）数 + 人名地名数 |
| 可验证断言 | 数字+单位（"XX万人""XX%"）的数量 |
| 反方回应 | 匹配"有人认为……但是""争议在于""也有人质疑" |

### 计算公式（建议）

```
鸡汤指数 = (
    你字率 × 0.25 +
    零出处扣分 × 0.35 +
    比喻密度/3 × 0.20 +
    结尾模板命中 × 0.10 +
    高情感词密度 × 0.10
)

真深度指数 = (
    出处密度归一化 × 0.5 +
    可验证断言归一化 × 0.3 +
    反方回应命中 × 0.2
)
```

如果鸡汤指数 > 阈值（建议 0.6），在 L2 中额外扣分或直接标记 ⚠️ 供 L3 复核。

### 实现位置

`bili_tool/scoring.py` — 在 `score_l2()` 或 `score_l2_auto()` 中加入，作为 L2 的附加维度。字幕采样已有的，直接对采样文本跑正则即可，不增加 API 调用。

## 三、附：本次发现的其他小问题

1. **推荐理由生成太泛**：当前推荐理由只看"长视频+评分"，不会根据用户偏好解释为什么推。视频1 的推荐理由写"长视频（42分钟），符合你对深度内容的需求"——实际用户完全不喜欢。建议推荐理由也接 LLM 或者至少关联画像维度。

2. **精校批注模板化**：当前精校的 💡 亮点大多是"生动""形象""逻辑清晰"这类套话，缺乏批判性。可以在 SYSTEM_PROMPT 里加一句："批注不要泛泛而谈，必须指出具体值得关注或值得质疑的点"。

3. **笔记中已交流复选框数量统计有误**：`cmd_daily()` 第327行用 `latest.count("✅ 已阅")` 统计总数，用 `latest.count("- [x]")` 统计已阅数。但现在笔记模板里同时有 `已阅` 和 `已交流` 两组复选框，count 会混在一起数错。应改为精确匹配 `"✅ 已阅\n- [x]"` 或按视频条目逐条解析。
