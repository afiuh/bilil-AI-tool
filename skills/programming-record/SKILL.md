## 用途

与用户协作编程时，将每个关键决策——从架构方向到代码细节——按决策树结构实时记录下来。不是事后补，是边做边写。

用户不需要会编程。用户负责设计判断和方向决策，AI负责执行和记录。

## 决策树结构

每个决策是一个节点，包含固定六字段：

1. **背景**：为什么要做这个决策
2. **AI的初始方案**：AI提出的第一个方案（可能是后来被否的）
3. **用户的判断**：用户的原话 + 否定了什么 + 为什么否定
4. **最终方向**：讨论后的最终方案
5. **相关commit**：Git提交的SHA（方便追溯代码）
6. **教训**：从这次决策中学到了什么

节点可以嵌套——宏观大决策（项目架构）下面有子决策（缓存设计），子决策下面有孙决策（缓存格式选择）。

树的深度 = 用户对这个问题追问了多少层。深度越深说明决策过程越折腾——好的方向一步到位，错的方向被用户连续追回。

## 触发方式

用户说"记录决策"→ AI立即写日志→ 用户审→ 确认→ AI继续写代码。

用户的确认同时确认了两样：代码方向 + 记录内容。不是事后补——是决策和记录绑定。

## AI行为约束

写日志时：
- 如实记录AI被否的方案——不美化、不省略、不找借口
- 如实记录用户的原话——尤其是纠正和批评的原话
- 不要只写最终方案——拉扯过程比最终方案更有价值
- 每个commit写清SHA（短格式即可）
- 教训提炼要具体——不是"要沟通好"这种空话，是"补丁无效时换根因那一层"
- 如果用户说"记错了"或"不对"，立刻修正，不要辩解

审查时：
- 用户只需要批注标记 "<!-- 不对，原因是xxx -->"
- AI根据标记修改后重新提交确认

## 文档位置

用户指定的目录（如 Obsidian 笔记/笔记/编程记录/），文件名为 `<项目名>_过程实现记录.md`。

每个项目一个文件，不混在一起。

## 索引

项目目录下的 README.md 作为全局索引：
- 列出所有项目的过程记录文件
- 每行格式：`- [项目名](项目名_过程实现记录.md) — 一句话描述 — X个决策`
- 每次新增决策后自动更新索引

## 示例

参考 bilil-AI-tool 项目的记录文件。该文件展示了：
- 决策嵌套树的完整格式
- AI被用户多次纠正的过程如实记录（GPU转录的8轮拉扯）
- 用户的核心定性被保留原话
- 教训提炼的具体程度
- 附：关键决策的完整讨论过程

## 通用性

这个系统不依赖任何特定项目类型。适用于：
- 从零开始的新项目
- 已有项目的重构
- 任何需要用户做方向判断 + AI做代码执行的协作场景

用户的设计判断力通过这个记录系统不断积累——每个项目产生的教训在下个项目启动前翻一遍。


## 迭代机制

这个 skill 本身也在被记录——每次用这个系统做完一个项目后，回头看 skill 本身哪里不够用：

### 触发迭代的信号
- 记录时反复出现同一类遗漏（比如总是忘了写commit SHA）→ skill里补强制规则
- 用户审查时反复指出同一类问题（比如"教训写得太空泛"）→ AI行为约束里加具体示例
- 新项目有新需求（比如跨项目对比、教训自动汇总）→ 加到skill的功能描述里

### 迭代方式
每个项目结束后，用户说"迭代 programming-record skill"→ AI回顾本次项目的记录过程→提skill改进建议→用户确认→更新skill版本号。

### 版本记录
skill文件底部追加版本日志：
```
## 版本历史
- v1.0.0: 初始版本，bilil-AI-tool项目验证
- v1.1.0: （待下一个项目结束后填写）
```
