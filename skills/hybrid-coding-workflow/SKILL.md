# Hybrid Coding Workflow v2.0

融合 v1.9 语义元动作体系 + Hermes Agent 原生能力的编码工作模式。

## 最高行为准则

**讨论确认制**。发现异常时只能分析根因、提出方案、等待确认，禁止直接动手。

三条红线：
- ❌ 未讨论根因就写代码
- ❌ 碰壁不分析就换方案  
- ❌ 换方案不征求用户同意

违反时立即停止、道歉、提出补救方案。

---

## 四级策略

```
L0 快速模式  → Bug修复/typo/单行改动
             → 直接干，不提SOP。事后可选经验卡片。
             
L1 标准模式  → 单文件、简单功能
             → 蓝图(简版) → 实现 → 自动验证 → Git提交
             → 中间暂停1次：蓝图后等确认

L2 完整SOP   → 多文件、新模块、架构级
             → 阶段一(架构设计)→【用户确认】
             → 阶段二~四(拆解→TDD→实现)→AI自动循环
             → 仅遇到无法自主解决的问题时暂停

L3 探索模式  → 不确定方向、调研、原型
             → 快速出选项/方案，不等确认
             → 结果标注⚠️探索性质
```

## 启动协议

每个开发任务开始前，先声明级别：

```
📋 任务分级：L0 / L1 / L2 / L3
📝 理由：xxxxx
```

然后进入对应流程。

## 元动作标注（精简版）

只在代码中标注高风险操作：

| 标签 | 触发 |
|------|------|
| `# [IO]` | 文件读写、网络请求、API 调用 |
| `# [ERR]` | 异常捕获、错误处理 |
| `# [DB]` | 数据库读写操作 |

跳过渲染/条件/转换等低风险标注，减少噪音。

## 工程规范（继承 v1.9）

- **存储配捕获**：所有 IO 操作必须包裹异常处理
- **通信配超时**：所有网络请求必须带 timeout
- **禁止裸 except**：必须指定异常类型
- **代码写完自动验证**：pytest / lint / 实际运行
- **每文件 Git 提交**：L2 模式每文件完成后 commit


## TDD 集成（v2.1 新增）

L1/L2 模式的阶段二~四自动集成 test-driven-development skill：

### 自动化 TDD 循环

```
阶段二：拆解 → 列出测试骨架
阶段三：蓝图 → 先写测试（RED），验证失败
阶段四：实现 → 最小代码通过（GREEN）→ 重构 → commit
```

### AI 自主执行规则

- 每个函数先写测试，终端运行 pytest 确认失败
- 写最小代码让测试通过，再次运行确认绿色
- 全部测试通过后重构清理
- 每文件完成后自动 git commit
- 测试失败 → AI 自行分析原因并修复
- 3 次修复仍失败 → 暂停询问用户

### 与 TDD Skill 联动

加载本 skill 时自动同时加载 `test-driven-development` skill。
违反 TDD 铁律（未先写测试就写代码）→ 删除代码重来。

## 经验卡片

格式简化为 YAML frontmatter + 规则：

```yaml
---
id: EXP-001
level: L0/L1/L2/L3
tags: [IO, ERR]
---
# 规则内容
所有 fetch() 必须配置 timeout + try-catch
```

存储：用 Hermes `memory` 工具（高频规则）+ `skill` 工具（模式级规则）。
编码过程中遇到重复错误，自动提议创建经验卡片。

## 确认制

| 级别 | 确认次数 | 确认点 |
|------|---------|--------|
| L0 | 0 | 无 |
| L1 | 1 | 蓝图后 |
| L2 | 1 | 仅阶段一(架构设计)后确认 |
| L3 | 0 | 无 |

L2 阶段二~四由 AI 自动执行 TDD 循环（写测试→看失败→写代码→看通过→重构→commit），
遇到无法自主解决的问题（设计歧义、API限制、外部依赖缺失）时暂停询问用户。

## 与 v1.9 原版的差异

| 改动 | 原版 | 融合版 |
|------|------|--------|
| 适用场景 | 全部严格SOP | 按任务分级 |
| 确认频率 | 每阶段必等 | L0/L3不等，L1少等 |
| 蓝图 | 纯伪代码 | 蓝图+测试骨架 |
| 验证 | 人类手动 | 自动 pytest/lint |
| 经验 | MD卡片手动引用 | memory+skill自动加载 |
| 元动作 | 8+标签 | 3个核心标签 |
| 执行环境 | Cursor | Hermes Agent (真实运行) |
